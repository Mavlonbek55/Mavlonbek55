## 🧭 How I work

| Principle | In practice (see [hotel-booking](https://github.com/Mavlonbek55/hotel-booking)) |
|---|---|
| **Decisions are documented** | Architecture Decision Records for the modular monolith, availability cache and booking concurrency |
| **Boundaries are enforced** | Four modules (Rooms, Reservations, Payments, Notifications) checked with Import Linter |
| **Correctness lives in the database** | PostgreSQL exclusion constraint as the last line of defence against double booking |
| **Measure before optimising** | Redis cache with an on/off switch and a measurement script for baseline vs cached runs |
| **Contracts first** | OpenAPI specification for the HTTP API |
| **Reproducible environments** | Docker Compose for PostgreSQL and Redis |
